# PlanFlow AI 产品原型功能说明

## 文档目的

本文档用于描述 PlanFlow AI 原型图中每个页面的功能、交互、字段和验收标准，供 AI 编码 Agent 对照开发。

产品核心流程：

1. 创建学习计划
2. 设置每周可学习时间
3. 获取飞书忙闲并计算真实可用时间
4. AI 拆解学习任务
5. 生成内部日历排程
6. 学习复盘并顺延未完成任务

## 页面 1：创建学习计划

### 页面目标

让用户输入学习目标和计划周期，创建一个待排程的学习计划。

### 页面入口

左侧导航点击「计划」，进入创建学习计划流程。

### 页面模块

#### 左侧导航

包含：

- 首页
- 计划
- 日历
- 任务
- 数据
- 设置
- 用户菜单

当前选中项：计划。

#### 主表单区域

标题：创建学习计划

说明文案：告诉用户输入学习目标后，AI 会生成个性化计划。

字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 学习目标 | 文本输入框 | 是 | 用户输入想学习的内容，例如“掌握 Next.js 全栈开发” |
| 总学习时长 | 数字输入框 | 是 | 单位为小时，必须大于 0 |
| 开始日期 | 日期选择器 | 是 | 学习计划开始日期 |
| 截止日期 | 日期选择器 | 是 | 必须晚于开始日期 |

按钮：

| 按钮 | 行为 |
| --- | --- |
| 下一步 | 校验表单，通过后进入「每周可学习时间」页面 |

### 校验规则

- 学习目标不能为空。
- 总学习时长必须大于 0。
- 开始日期不能为空。
- 截止日期不能为空。
- 截止日期必须晚于开始日期。
- 校验失败时，在对应字段下展示中文错误提示。

### 开发说明

- 前端页面可对应 `/plans/new` 或创建流程组件。
- 表单状态可以先放在客户端组件本地状态中。
- 当前页面不需要直接调用 AI。
- 点击「下一步」后，应把计划基础信息传递给下一步流程。

### 验收标准

- 用户可以填写完整计划信息。
- 用户点击下一步后能进入每周可学习时间配置。
- 非法输入会被拦截，并显示清晰错误提示。

## 页面 2：每周可学习时间

### 页面目标

让用户按星期配置每周可学习时间，支持不同星期配置不同时间段。

### 页面模块

标题：设置每周可学习时间

说明文案：选择每周可以投入学习的时间段，AI 将在这些时间内安排学习任务。

### 时间配置区域

每一行代表一个星期：

- 周一
- 周二
- 周三
- 周四
- 周五
- 周六
- 周日

每行包含：

| 控件 | 说明 |
| --- | --- |
| 星期名称 | 展示当前星期 |
| 启用开关 | 控制该星期是否可学习 |
| 时间段标签 | 展示已添加的时间段，例如 `20:00-22:00` |
| 删除按钮 | 删除某个时间段 |
| 添加时间按钮 | 给当前星期新增一个时间段 |

### 原型中的示例数据

- 周一：20:00-22:00
- 周二：20:00-22:00、09:00-12:00
- 周三：20:00-22:00
- 周四：20:00-22:00
- 周五：20:00-22:00、09:00-11:00
- 周六：无
- 周日：无

### 按钮

| 按钮 | 行为 |
| --- | --- |
| 上一步 | 返回创建学习计划页面 |
| 下一步 | 校验每周可学习时间，通过后进入飞书忙闲同步页面 |

### 校验规则

- 至少需要配置一个可学习时间段。
- 未启用的星期不能提交时间段。
- 同一天可以配置多个时间段。
- 同一天多个时间段不能重叠。
- 时间段结束时间必须晚于开始时间。
- 时间格式必须为 `HH:mm`。

### 开发说明

- 可复用 `packages/shared/src/availability.ts` 中的可用时间校验函数。
- 页面数据结构建议使用：

```ts
type WeeklyAvailabilityInput = {
  weekday: 0 | 1 | 2 | 3 | 4 | 5 | 6;
  enabled: boolean;
  ranges: {
    startTime: string;
    endTime: string;
  }[];
};
```

### 验收标准

- 用户可以按星期启用或关闭可学习时间。
- 用户可以给同一天添加多个时间段。
- 用户可以删除已有时间段。
- 非法时间段会被拦截。
- 点击下一步后进入飞书忙闲同步页面。

## 页面 3：飞书忙闲同步

### 页面目标

展示用户配置的可学习时间、飞书忙碌时间，以及扣除忙碌时间后的真实可用时间。

### 页面模块

#### 顶部操作

| 按钮 | 行为 |
| --- | --- |
| 重新同步 | 重新调用 CalendarProvider 获取忙碌时间 |

### 三栏信息区

#### 第一栏：可学习时间

展示用户在上一页配置的原始每周可学习时间。

状态文案：未同步设置。

示例：

- 周一：20:00-22:00
- 周二：20:00-22:00、09:00-12:00
- 周三：20:00-22:00
- 周四：20:00-22:00
- 周五：20:00-22:00、09:00-11:00
- 周六：无
- 周日：无

#### 第二栏：扣除冲突后真实可用时间

展示系统扣除飞书忙碌时间后的真实可学习时间。

每个星期右侧可展示绿色对勾，表示已完成冲突计算。

#### 第三栏：飞书忙碌时间

展示本周从飞书或 MockFeishu 获取到的忙碌事件。

原型示例：

- 09:00-10:30 临时会议
- 10:30-12:00 团队周会
- 09:00-11:00 临时会议

### 图例

底部图例包含：

- 可学习时间
- 忙碌时间
- 可用时间

### 开发说明

- MVP 使用 `MockFeishuCalendarProvider`。
- 真实飞书后续通过相同 `CalendarProvider` 接口替换。
- 当前页面不需要创建飞书事件，只需要展示忙闲读取和真实可用时间计算结果。
- 点击「重新同步」应重新获取忙碌时间并刷新真实可用时间。

### 验收标准

- 页面可以展示原始可学习时间。
- 页面可以展示 MockFeishu 忙碌时间。
- 页面可以展示扣除冲突后的真实可用时间。
- 忙碌时间占用可学习时间时，对应时间段不可再用于排程。
- 同步失败时显示错误状态，并允许重新同步。

## 页面 4：AI 任务拆解确认

### 页面目标

展示 AI 根据学习目标生成的学习任务，让用户确认后生成排程。

### 页面模块

标题：AI 已为你生成学习任务计划

副标题展示计划总时长和日期范围。

示例：

- 总计：60 小时
- 日期：2024-05-20 至 2024-07-14

### 任务表格

表格字段：

| 字段 | 说明 |
| --- | --- |
| 阶段 | 学习阶段，例如基础、Hooks、Router、项目实战 |
| 任务 | AI 生成的具体学习任务 |
| 预计时长 | 当前任务预计学习时间 |
| 验收标准 | 用户完成任务后应达到的结果 |

### 原型中的阶段示例

#### 基础

- 学习 React 基础语法
- 学习 JSX 与组件通信
- 使用 Vite 搭建项目

#### Hooks

- 学习 useState 与 useEffect
- 自定义 Hook 实践

#### Router

- React Router 基础
- 嵌套路由与参数传递

#### 项目实战

- 实战：博客系统开发
- 部署上线与性能优化

### 按钮

| 按钮 | 行为 |
| --- | --- |
| 上一步 | 返回飞书忙闲同步页面 |
| 生成排程 | 调用排程逻辑，根据真实可用时间生成学习日历 |

### 开发说明

- AI 服务应封装在独立 service 中。
- MVP 可以使用 mock AI provider。
- AI 输出必须经过结构校验。
- AI 任务总预计时长应接近用户填写的总学习时长。
- 当前页面可以先只做确认，不提供编辑能力；后续可扩展为可编辑任务表格。

### 验收标准

- 页面展示 AI 生成的任务分组。
- 每个任务包含阶段、标题、预计时长和验收标准。
- 用户点击生成排程后，系统进入内部日历排程看板。
- AI 输出结构非法时，页面显示错误提示。

### 验收标准

- 用户可以看到一周学习日程。
- 用户可以区分学习任务和飞书忙碌时间。
- 今日任务和进度统计能正确展示。
- 用户可以导出 `.ics`。
- 页面具备空状态、加载状态和错误状态。

## 页面 6：学习复盘与顺延

### 页面目标

在学习时间结束后，让用户提交本次学习复盘，并在未完成时自动顺延剩余任务。

### 页面形态

弹窗 Modal。

标题：复盘本次学习任务

右上角提供关闭按钮。

### 任务信息

展示当前复盘的学习任务信息：

| 字段 | 示例 |
| --- | --- |
| 任务标题 | React 基础语法 |
| 日期 | 05/20 周一 |
| 原计划时间 | 20:00-22:00 |

### 完成情况

单选项：

- 已完成
- 部分完成
- 未完成
- 跳过

原型中选中：未完成。

### 表单字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 实际学习时长 | 数字输入 | 单位分钟 |
| 原因 | 多行文本 | 用户填写未完成或延期原因 |
| 顺延建议 | 输入框或展示框 | 系统根据真实可用时间计算出的建议顺延时间 |

原型示例：

- 实际学习时长：30 分钟
- 原因：临时有事，时间不足
- 顺延建议：顺延到周三 19:30-20:30

### 操作按钮

| 按钮 | 行为 |
| --- | --- |
| 不顺延 | 只记录复盘，不生成新的学习日程 |
| 顺延到其他时间 | 打开可选时间列表或时间选择器 |
| 确认顺延 | 保存复盘，并按建议时间生成顺延日程 |

### 顺延规则

- 已完成：任务进度更新，不产生顺延。
- 部分完成：剩余分钟数重新进入待排程队列。
- 未完成：原计划未完成部分重新排程。
- 跳过：原日程标记为跳过，任务重新排程。
- 顺延时必须使用当前时间之后的真实可用时间。
- 顺延时必须避开飞书忙碌时间。
- 顺延时需要遵守 `rescheduleBufferMinutes`。
- 如果截止日期前容量不足，返回容量不足警告。

### 开发说明

- 复盘逻辑应放在 `lib/review` 或独立 review service 中。
- 顺延排程应复用 scheduler，不在弹窗组件里写排程算法。
- 提交复盘后，需要更新：
  - 当前 session 状态
  - task 进度
  - 新生成的 rescheduled session
  - 日历视图
  - 进度统计

### 验收标准

- 用户可以提交学习复盘。
- 已完成不会生成顺延。
- 部分完成、未完成、跳过可以触发顺延。
- 顺延后的日程展示在内部日历中。
- 顺延不能与忙碌时间冲突。
- 容量不足时显示明确提示。

## 全局导航说明

所有页面左侧导航保持一致：

| 导航项 | 功能 |
| --- | --- |
| 首页 | 后续展示总览 |
| 计划 | 创建和管理学习计划 |
| 日历 | 查看学习日历和忙碌时间 |
| 任务 | 查看 AI 拆解任务 |
| 数据 | 查看学习进度和统计 |
| 设置 | 配置 AI、日历 provider 等 |

MVP 阶段可以先实现「计划」和「日历」主流程，其余导航项可显示占位状态。

## 核心开发边界

### 前端职责

- 表单输入
- 页面流程控制
- 状态展示
- 错误提示
- 日历和任务展示
- 复盘弹窗交互

### 后端职责

- 保存计划
- 保存可学习时间
- 调用 AI provider 生成任务
- 调用 CalendarProvider 获取忙碌时间
- 执行真实可用时间计算
- 执行排程算法
- 保存日程和复盘
- 导出 `.ics`

### 共享逻辑职责

应放在 `packages/shared` 或独立模块中：

- 时间段类型
- 星期枚举
- 可用时间校验
- 时间段重叠判断
- 错误码类型

### 排程逻辑职责

应放在 `packages/scheduler` 中：

- 根据真实可用时间生成学习日程
- 支持长任务拆分
- 避开忙碌时间
- 支持容量不足提示
- 支持顺延时应用缓冲时间

## 页面开发建议顺序

建议 AI Agent 按以下顺序开发：

1. 可用时间校验
2. MockFeishuCalendarProvider
3. 真实可用时间计算
4. 排程算法
5. AI mock 任务生成
6. 创建计划 API
7. 生成计划 API
8. 内部日历页面
9. 复盘和顺延
10. `.ics` 导出
11. UI 状态打磨

## MVP 页面验收总标准

- 用户可以从创建计划开始，完成完整流程。
- 用户可以配置不均匀的每周学习时间。
- 系统可以展示并扣除飞书忙碌时间。
- AI 可以生成结构化学习任务。
- 系统可以把任务排入真实可用时间。
- 学习日程不会和忙碌时间冲突。
- 用户可以在学习后提交复盘。
- 未完成任务可以顺延。
- 用户可以在日历看板查看任务和进度。
- 用户可以导出 `.ics` 文件。
