# PlanFlow AI PRD

## 背景

PlanFlow AI 是一个学习计划助手，用于把学习目标转成可执行的日历计划。第一版聚焦技术学习场景，例如“用 30 小时学习 React”，避免做成宽泛的 Notion 式任务管理工具。

## 目标用户

- 正在学习新框架或新技术栈的前端开发者。
- 需要结构化学习计划的求职者。
- 每周可学习时间不固定的独立学习者。

## 核心痛点

- 用户知道学习目标，但不知道如何拆成可执行任务。
- 用户每周空闲时间不均匀，并不是每天都有固定学习时间。
- 用户未来日历会动态变化，例如临时会议会占用原本计划学习的时间。
- 学习执行经常脱离计划，某个时间段结束后可能只完成一部分，甚至完全没完成。
- 普通 Todo 应用只记录任务，不负责决定任务应该什么时候发生。
- 日历提醒很有价值，但更关键的是读取真实忙闲，避免把学习任务排进会议时间。

## 产品定位

PlanFlow AI 不是通用任务管理工具，而是 AI 学习计划与日历排程助手。

产品承诺：

> 输入学习目标和每周可用时间，PlanFlow AI 结合飞书忙闲生成可执行学习日历，并在复盘后自动顺延未完成内容。

## MVP 功能

### 创建学习计划

用户可以创建一个计划，包含：

- 计划标题
- 学习目标描述
- 总学习时长
- 开始日期
- 截止日期
- 每周可用时间规则

验收标准：

- 用户可以通过表单创建计划。
- 总时长必须大于 0。
- 截止日期必须晚于开始日期。
- 至少配置一个每周可用时间段。

### 每周可用时间配置

用户按星期配置可学习时间：

- 周一到周日可以分别启用或不启用。
- 每个星期可以配置 0 个或多个时间段。
- 示例：周六可以配置 `09:00-12:00` 和 `14:00-16:00`。

验收标准：

- 某一天可以没有可用时间。
- 某一天可以有多个可用时间段。
- 结束时间早于开始时间时需要拦截。
- 同一天重叠的时间段需要拦截。

### AI 任务拆解

系统把学习目标转换成学习任务。

每个任务包含：

- 学习阶段
- 任务标题
- 任务描述
- 预计耗时
- 优先级
- 验收标准

验收标准：

- AI 输出会被解析成结构化任务。
- 任务总预计时长应接近用户填写的总学习时长。
- 无效 AI 输出需要被拒绝，并给出可理解的错误提示。
- AI 服务需要独立封装，不能散落在业务路由中。

### 自动排程

排程器把任务安排到开始日期和截止日期之间的真实可用时间段中。真实可用时间由“用户每周可学习时间”扣除“飞书日历忙碌时间”得到。

验收标准：

- 日程只生成在用户配置的可用时间段内。
- 日程不能与飞书忙碌时间冲突。
- 长任务可以拆分到多个日程块。
- 日程包含开始时间、结束时间、关联任务和状态。
- 如果可用时间不足，需要清楚提示未排完的任务时长。

### 日历冲突感知

系统需要通过日历 provider 获取外部忙碌时间。MVP 使用 `MockFeishuCalendarProvider` 模拟飞书忙闲；真实飞书 API 后续替换同一接口。

验收标准：

- 系统可以获取指定日期范围内的忙碌时间段。
- 系统可以把忙碌时间从每周可学习时间中扣除。
- 如果会议占用了原计划学习时间，受影响日程需要标记为冲突或进入重新排程。
- 真实飞书接入失败时，系统仍可使用 mock 忙闲和 `.ics` 导出完成演示。

### 日历和任务视图

界面展示：

- 计划概览
- 今日学习任务
- 周日历
- 任务列表
- 进度汇总

验收标准：

- 用户可以看到每个日期安排了哪些学习日程。
- 用户可以把任务或日程标记为完成。
- 完成后进度会更新。
- 空状态、加载状态和错误状态需要可见。

### 日历导出

用户可以把已排程日程导出为 `.ics` 文件。

验收标准：

- 导出内容包含所有已排程日程。
- 日历事件标题包含学习任务标题。
- 事件描述包含计划名称和验收标准。
- 即使没有飞书集成，也可以使用导出能力。

### 学习复盘和顺延

每个学习日程结束后，用户需要进行复盘，记录本次执行情况。

复盘状态：

- 已完成
- 部分完成
- 未完成
- 跳过

复盘字段：

- 实际学习分钟数
- 未完成原因
- 剩余分钟数
- 是否继续当前任务

验收标准：

- 用户可以对已结束日程提交复盘。
- 部分完成或未完成时，剩余时长会回到待排程队列。
- 系统会基于后续真实可用时间自动顺延剩余任务。
- 顺延结果需要更新内部日历视图，并可重新导出或同步日历。

## 非 MVP 功能

- 真实飞书 OAuth、查询忙闲和事件创建的生产级接入。
- 多用户团队协作。
- 付费系统。
- 高级推荐引擎。
- 移动端 App。
- 完整 RBAC 权限系统。
- 插件系统。

## 用户流程

1. 用户打开 PlanFlow AI。
2. 用户创建学习计划。
3. 用户按星期配置可用时间。
4. 用户点击生成计划。
5. AI 生成结构化学习任务。
6. 日历 provider 获取飞书忙闲。
7. 排程器扣除忙碌时间并生成日历日程。
8. 用户查看内部日历和任务列表。
9. 时间结束后，用户提交复盘。
10. 未完成任务自动顺延到后续真实可用时间。
11. 用户导出 `.ics` 或后续同步到飞书日历。

## 成功指标

- 用户可以在 3 分钟内生成完整学习日历。
- 一个 30 小时学习目标可以围绕不均匀的每周可用时间和模拟飞书忙闲完成排程。
- 未完成或部分完成的学习日程可以复盘并自动顺延。
- 生成结果足够清晰，可以用于面试演示。
- 即使真实 AI 或真实飞书 API 不可用，MVP 也能通过模拟 AI、MockFeishu 忙闲和 `.ics` 导出完整运行。
