# PlanFlow AI 设计规格

## 产品方向

PlanFlow AI 是一个 AI 学习计划与日历排程助手。它帮助用户把自然语言学习目标，例如“学习 React”，转换成结构化学习任务，并安排到具体日历时间块中。

MVP 面向个人学习者、正在切换技术栈的前端开发者，以及需要现实学习计划的求职者，而不是再做一个通用 Todo 工具。

## 核心问题

用户通常知道自己想学什么，也大概知道能投入多少时间，但不知道如何把目标拆成可执行任务，也不知道如何把任务放进不均匀的每周可用时间里。

PlanFlow AI 通过以下能力解决这个问题：

- AI 任务拆解
- 每周可用时间规则
- 飞书忙闲冲突感知
- 确定性排程
- 学习复盘和未完成任务顺延
- 日历展示与导出

## MVP 范围

MVP 包含：

- 创建学习计划，包含标题、目标描述、总时长、开始日期、截止日期和每周可用时间。
- 按星期配置可用时间。每个星期可以有 0 个或多个时间段。
- 生成结构化学习任务，包含标题、描述、预计分钟数、优先级、阶段和验收标准。
- 通过 `CalendarProvider` 获取外部忙碌时间，MVP 使用 `MockFeishuCalendarProvider` 模拟飞书忙闲。
- 只把任务排入扣除忙碌时间后的真实可用时间段。
- 必要时把长任务拆分到多个可用时间段。
- 展示计划概览、任务列表、今日任务和日历安排。
- 追踪任务状态：未开始、进行中、已完成、已延期。
- 在学习日程结束后提交复盘，未完成内容自动顺延。
- 导出 `.ics` 日历文件作为兜底能力。

飞书日历是核心集成目标。MVP 不强依赖真实飞书 OAuth，而是先用 provider 抽象和 mock 忙闲验证核心排程闭环，避免第三方配置阻塞第一版。

## 推荐架构

使用小型 TypeScript 全栈应用：

- 前端：React + TypeScript
- 全栈框架：Next.js App Router + React + TypeScript
- API 层：Next.js Route Handlers
- 数据库：Prisma + PostgreSQL
- UI：Tailwind CSS + shadcn/ui
- 校验：Zod
- AI 集成：独立服务，返回经过校验的结构化输出
- 日历 provider：独立接口，负责读取忙闲和创建外部日历事件
- 可用时间引擎：合并用户每周可用时间和日历忙碌时间
- 排程：独立纯函数模块，方便单元测试
- 复盘引擎：计算剩余任务量并触发顺延
- 日历导出：独立 `.ics` 生成模块

关键边界：

- `aiPlanningService`：把学习目标转换成结构化任务。
- `calendarProvider`：读取飞书忙闲，后续创建或更新飞书日历事件。
- `availabilityEngine`：把每周可用时间扣除忙碌时间，得到真实可用时间。
- `scheduler`：把任务和真实可用时间转换成日历日程。
- `reviewEngine`：处理复盘结果和未完成任务顺延。
- `calendarExportService`：把日程转换成 `.ics` 文件。
- API 层：校验输入并持久化计划、任务、可用时间和日程。
- React UI：管理计划创建、可用时间编辑、日历展示和状态更新。

## 数据流

1. 用户创建学习计划和每周可用时间规则。
2. 后端校验请求并保存计划草稿。
3. AI 服务生成结构化学习任务。
4. 后端校验 AI 输出并保存任务。
5. 日历 provider 获取计划范围内的飞书忙闲。
6. 可用时间引擎扣除忙碌时间，得到真实可用时间。
7. 排程器读取任务和真实可用时间，在截止日期前生成日程。
8. 前端展示生成的日历和任务列表。
9. 日程结束后，用户提交复盘。
10. 复盘引擎把未完成时长重新放回待排程队列，并触发顺延。
11. 用户导出 `.ics` 文件，后续也可以同步到飞书日历。

## 错误处理

- 每周可用时间非法时，在排程前返回校验错误。
- 同一星期内重叠的时间段需要被拒绝。
- 飞书忙闲获取失败时，可以回退到 mock 忙闲或提示用户使用 `.ics` 兜底。
- 排程前比较截止日期前的总可用时间和任务总时长。
- 如果容量不足，排程器返回部分日程和未排完任务。
- 复盘后如果剩余时长无法在截止日期前排完，需要提示容量不足。
- AI 输出必须先解析和校验，再持久化。
- 没有已排程日程时，日历导出需要清晰失败。

## 测试重点

- 每周可用时间校验。
- 忙碌时间扣除。
- 不均匀星期时间段下的排程。
- 任务拆分到多个日程。
- 可用时间不足处理。
- 复盘后的剩余任务顺延。
- AI 输出结构校验。
- API 请求和响应契约。
- 前端主流程：创建计划、生成任务、查看日程、提交复盘、顺延任务、导出日历。

## 待确认决策

- 第一版可以使用响应结构相同的模拟 AI 提供方，后续再在服务边界后接入真实 OpenAI。
- 认证可以先使用模拟或单用户模式。
- 飞书日历先设计成 provider 接口，MVP 使用 MockFeishu 忙闲验证核心逻辑，`.ics` 导出作为兜底能力。
